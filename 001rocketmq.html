RocketMQ

RabbitMQ 3.7.23 安装方案（调整安装路径至 /home/admintalu/u01/tool）

一、前置说明

  1. 安装环境：默认基于 Linux 系统（如 CentOS 7/8、Ubuntu 18.04+）
  2. 依赖要求：需先安装 Erlang 21.x（与 RabbitMQ 3.7.23 兼容）
  3. 目标路径：/home/admintalu/u01/tool
  4. 配置目标：确保服务地址为 paascloud-mq-rabbit:5672，默认用户 guest/guest

二、安装步骤

1. 准备工作：创建安装目录

# 创建安装目录并赋予权限
mkdir -p /home/admintalu/u01/tool
chmod -R 755 /home/admintalu/u01/tool

# 进入工作目录
cd /home/admintalu/u01/tool

2. 安装 Erlang 依赖

（1）下载 Erlang 21.3.8.24

# 下载 Erlang 源码包
wget https://github.com/erlang/otp/releases/download/OTP-21.3.8.24/otp_src_21.3.8.24.tar.gz

# 若下载缓慢，可手动下载后上传至此目录

（2）安装编译依赖

# CentOS 系统
yum install -y gcc gcc-c++ make perl openssl-devel ncurses-devel

# Ubuntu 系统
apt update && apt install -y gcc g++ make perl libssl-dev libncurses5-dev

（3）编译并安装 Erlang

# 解压源码包
tar -zxvf otp_src_21.3.8.24.tar.gz
cd otp_src_21.3.8.24

# 配置安装路径（指定到目标目录）
./configure --prefix=/home/admintalu/u01/tool/erlang \
--enable-smp-support --enable-threads --enable-sctp \
--enable-kernel-poll --enable-hipe --without-javac

# 编译安装
make -j 4
make install

（4）配置 Erlang 环境变量

# 编辑环境变量配置文件
vi ~/.bash_profile  # 个人用户
# 或 vi /etc/profile  # 系统全局

# 添加以下内容
export ERLANG_HOME=/home/admintalu/u01/tool/erlang
export PATH=$ERLANG_HOME/bin:$PATH

# 生效配置
source ~/.bash_profile  # 对应上面的配置文件

（5）验证 Erlang 安装

erl -version
# 预期输出：Erlang (SMP,ASYNC_THREADS,HIPE) (BEAM) emulator version 10.3.5.14

3. 安装 RabbitMQ 3.7.23

（1）下载 RabbitMQ 安装包

# 进入安装目录
cd /home/admintalu/u01/tool

# 下载 RabbitMQ 二进制包
wget https://github.com/rabbitmq/rabbitmq-server/releases/download/v3.7.23/rabbitmq-server-generic-unix-3.7.23.tar.xz

（2）解压安装包

# 安装 xz 解压工具（若未安装）
yum install -y xz  # CentOS
# 或 apt install -y xz-utils  # Ubuntu

# 解压
xz -d rabbitmq-server-generic-unix-3.7.23.tar.xz
tar -xvf rabbitmq-server-generic-unix-3.7.23.tar

（3）配置 RabbitMQ 环境变量

vi ~/.bash_profile  # 或 /etc/profile

# 添加以下内容
export RABBITMQ_HOME=/home/admintalu/u01/tool/rabbitmq_server-3.7.23
export PATH=$RABBITMQ_HOME/sbin:$PATH

# 生效配置
source ~/.bash_profile

4. 配置 RabbitMQ

（1）创建配置文件

# 创建配置文件目录
mkdir -p /home/admintalu/u01/tool/rabbitmq_server-3.7.23/etc/rabbitmq

# 编辑配置文件
vi /home/admintalu/u01/tool/rabbitmq_server-3.7.23/etc/rabbitmq/rabbitmq.conf

（2）添加核心配置

# 监听端口
listeners.tcp.default = 5672

# 允许 guest 用户远程访问
loopback_users.guest = false

# 数据存储路径
mqtt.ssl.cacertfile = /home/admintalu/u01/tool/rabbitmq_server-3.7.23/var/lib/rabbitmq/mnesia

5. 启动 RabbitMQ 服务

（1）启动服务

# 后台启动
rabbitmq-server -detached

（2）验证启动状态

# 查看状态
rabbitmqctl status

# 检查端口监听
netstat -tulnp | grep 5672

（3）启用管理界面（可选）

# 启用管理插件
rabbitmq-plugins enable rabbitmq_management

# 访问地址：http://服务器IP:15672，用户名/密码：guest/guest

6. 配置域名解析

# 在需要访问 RabbitMQ 的机器上配置
vi /etc/hosts

# 添加以下内容（替换为实际IP）
xxx.xxx.xxx.xxx  paascloud-mq-rabbit

三、常用命令

# 启动 后台
rabbitmq-server -detached
# 
rabbitmq-server 


# 停止
rabbitmqctl stop

# 查看状态
rabbitmqctl status

# 查看用户
rabbitmqctl list_users

四、注意事项

  1. 确保 /home/admintalu/u01/tool 目录有足够的读写权限
  2. 若使用非 root 用户安装，需确保该用户有目录操作权限
  3. 防火墙需开放 5672 端口（及 15672 管理端口）
  4. 若启动失败，可查看日志：/home/admintalu/u01/tool/rabbitmq_server-3.7.23/var/log/rabbitmq/

这个警告信息 Warning: PID file not written; -detached was passed. 是正常现象，并非错误，无需担心。

原因解释：

使用 -detached 参数启动 RabbitMQ 时，服务会在后台运行，此时默认默认不会写入 PID 文件（进程 ID 文件），因此会出现这个警告。这是 RabbitMQ 的正常行为，不影响服务的启动和运行。

验证服务是否成功启动：

可以通过以下命令确认 RabbitMQ 是否已经正常运行：

# 查看 RabbitMQ 状态
rabbitmqctl status

# 或查看进程
ps -ef | grep rabbitmq

# 或检查端口监听（5672 为默认端口）
netstat -tulnp | grep 5672

如果 rabbitmqctl status 命令能输出详细的服务状态信息（包含节点名称、内存使用、插件等信息），则说明服务已成功启动。

补充说明：

如果希望避免这个警告，可以不使用 -detached 参数，直接在前台启动（但退出终端时服务会停止）：

# 前台启动（日志会实时输出到终端）
rabbitmq-server

但在实际生产环境中，推荐使用 -detached 后台启动，即使有这个警告也不影响使用。
